## 5. Найденный блокер (уже исправлен в HEAD)

Signed APK, собранный из `a03cee8`, при обновлении с реальной старой БД **падает при запуске**:

```
SQLiteException: no such table: models (code 1 SQLITE_ERROR):
, while compiling: ALTER TABLE models ADD COLUMN isAvailable INTEGER
    at AppDatabase$Companion$MIGRATION_6_7.migrate(AppDatabase.kt:98)
```

Причина: в `a03cee8` `MIGRATION_4_5` был пустым (`= Unit`) на основании того, что «экспортированные схемы 4 и 5 идентичны».
Для исторического пути это неверно: реальные БД v1 и v4 (v0.1.0, v1.1.0, v1.3.3) таблицы `models` не содержат,
поэтому после no-op миграции `MIGRATION_6_7` не находит таблицу и приложение не открывается.

Исправлено в `947214d` («Fix desktop import and chat workflows; verify recovery and legacy migrations»):
`MIGRATION_4_5` теперь проверяет наличие `messages.attachments_json` и выполняет `CREATE TABLE IF NOT EXISTS models`.

Падение воспроизведено на двух реальных путях (install -r архивного signed APK, сертификат тот же):

| Исходная БД | Наблюдение |
|---|---|
| v1, APK v0.1.0 | `no such table: models` в `MIGRATION_6_7`, FATAL EXCEPTION, процесс умирает |
| v4, APK v1.3.3 (126 скачиваний) | то же: SQLiteLog `no such table: models` + FATAL EXCEPTION, приложение не стартует |

Следствие: **релиз собирать только с коммита не старше `947214d`**; любой более ранний артефакт (включая архивный signed APK) публиковать нельзя.
Именно этот дефект и был причиной делать гейт: без него «зелёные» unit-тесты не показывали падение на реальной пользовательской базе.

## 6. Сопутствующие находки

1. **versionCode локальной сборки.** Локально `versionCode` берётся из `version.properties` (`2.0.0` → `20000`) и равен опубликованному 2.0.0.
   Локально собранный APK нельзя поставить обновлением поверх публичного релиза. В CI `versionCode` выводится из тега (`VERSION_NAME`),
   поэтому релизный тег должен быть выше 2.0.0 (например `v2.1.0`); иначе обновление не установится.
2. **Старые клиенты не синхронизируют каталог.** `findPromptsDirectory` у v0.1.0–v1.3.3 берёт первую папку с именем `prompts`,
   а в ветке `master` репозитория каталога раньше по алфавиту идёт `aiprompts-kmp/…/ui/prompts` (JSON там нет) — отсюда «Не найдены промпты в репозитории».
   Значит, обновляющийся пользователь приходит с пустым/устаревшим каталогом и импорт делает уже новый клиент.
   Если захочется вернуть синхронизацию старым клиентам, достаточно убрать архивный `aiprompts-kmp` из `master`.
3. **`models.isAvailable = NULL` после 6→7 — не дефект.** Поле объявлено как `Boolean? = null` («не проверена»), DAO сортирует NULL отдельной ветвью.
4. Публичный APK 2.0.0 побайтово совпадает с архивной копией, то есть архив снимков достоверен.

## 7. Что осталось непроверенным

- Комбинация «release-signed APK из HEAD, поставленный поверх старого релиза», локально не собирается: пароль keystore есть только в GitHub secrets.
  Покрыто по частям: (а) сертификат новой сборки совпадает с сертификатом опубликованного 2.0.0 — это же проверяет release-workflow;
  (б) миграции кода HEAD проверены на тех же реальных БД. Финальную сборку и подпись выполняет release-job CI.
- APK v0.3.0 и v1.1.0 не прогонялись end-to-end (их схемы 1 и 4 уже покрыты v0.1.0 и v1.3.3).
- Шаг 3 плана (чистый checkout, unit/lint, EXE/MSI, SHA-256 релиза, fresh install, запуск installer/uninstaller, smoke-тест каталога, личного промпта, провайдера и улучшения промпта) не выполнялся — это следующий этап.
- Импорт каталога после миграции в одном прогоне дал 935 строк, в другом в окне ожидания не успел; сам импорт 932 записей проверен в проекте ранее, отдельно не переисследовался.

## 8. Как воспроизвести

```powershell
# установить опубликованный APK, дать создать БД, снять её (нужен root)
adb install -r AiPromptMaster-release-v0.0.2.2.-2.apk
adb shell am force-stop com.arny.aipromptmaster
adb shell "cp /data/data/com.arny.aipromptmaster/databases/AiPromptMasterDB* /sdcard/"
# подложить БД в сборку нового кода (или install -r подписанного APK) и проверить версию/данные
adb shell "cp /data/data/com.arny.aipromptmaster/databases/AiPromptMasterDB-wal /sdcard/"   # схема лежит в WAL, тянуть вместе с -wal и -shm

# instrumentation
.\gradlew.bat :app:connectedDebugAndroidTest `
  -Pandroid.testInstrumentationRunnerArguments.class=com.arny.aipromptmaster.DatabaseMigrationTest
```
